### 0e. Explore an existing repo first
In a repo that already has code, the first teammate is an explore teammate, started at the same time as groundwork's probe (0g; neither changes a file):
`compose explore --project <slug> | compose crew start --project <slug> --role explore --title explore --brief -`.
It maps the code through trail only, in under 3 minutes, and appends a codebase brief of at most 40 lines to the feature's Notes: entry points, where the feature plugs in (file:line), patterns and helpers to reuse, the test setup and commands, risks.
Wayfinder (0b) and the plan read that brief: ask only what the code does not already answer, and plan tasks onto the files and helpers it names.
It is a gate, not a nicety: in a repo with code, no wayfinder question is asked and no plan, story, or task is written until the brief is on the feature. A question or task built on what the code "probably" does is an assumption the product owner never agreed to; check it in the code first (`trail ask`, `trail callers`), and if the code cannot settle it, say so in the question.
A new or empty repo has nothing to explore: skip this step.
